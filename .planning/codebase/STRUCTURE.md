## Directory Purposes

**`src/background/`:**
- Purpose: Extension background service (long-lived, persistent)
- Contains: Keyboard command handler, Chrome API integration
- Key files: `background.ts` — sole file; listens on `chrome.commands.onCommand`, queries active tab, sends toggle message

**`src/popup/`:**
- Purpose: Extension popup UI (shown when user clicks extension icon)
- Contains: Settings (test ID attribute), "Open picker now" button, keyboard help text
- Key files: `main.ts` — vanilla DOM builder (no React); `popup.css` — minimal styling

**`src/content/`:**
- Purpose: Content script (injected into user's web page, runs in page JS context)
- Contains: Overlay lifecycle, event handlers (mousemove, click), highlight tracking, panel rendering, verification UI
- Key files:
  - `index.ts` — entry point; message listener, overlay toggle
  - `event-manager.ts` — overlay/panel DOM creation, all event listeners
  - `highlighter.ts` — visual styling (CSS injection, box positioning)

**`src/core/`:**
- Purpose: Pure JavaScript selector generation logic (no DOM side effects)
- Contains: Candidate generators (XPath, CSS, Playwright), scorers, verification, utilities
- Key files:
  - `selector-engine.ts` — main entry point called by content script after element click
  - `xpath-generator.ts`, `css-generator.ts` — strategy-based candidate collection
  - `xpath-scorer.ts`, `css-scorer.ts`, `playwright-scorer.ts` — ranking by weighted factors
  - `attribute-analyzer.ts` — semantic attribute extraction
  - `locator-verifier.ts` — runtime evaluation of user-typed locators
  - `uniqueness-checker.ts` — validation helpers

**`src/adapters/`:**
- Purpose: Framework-specific locator formatting (Playwright, Cypress, Selenium)
- Contains: Locator generation specific to each test framework's syntax
- Key files: `playwright-adapter.ts` — 12 Playwright locator formats; others are helpers

**`src/types/`:**
- Purpose: Shared TypeScript type definitions
- Contains: LocatorFormat, LocatorResult, ElementLocators, ScoredXPath, ScoredCSS, ScoredPlaywright, score breakdowns
- Key files: `locator.types.ts` — single file; imports by all core modules

**`src/utils/`:**
- Purpose: Utility helpers used across modules
- Contains: DOM API wrappers (querySelector, XPath eval, sibling introspection), string escaping
- Key files: `dom-utils.ts`, `string-utils.ts`

**`public/`:**
- Purpose: Build output directory for extension files
- Generated by Vite during build; committed to git for fast installs
- Contains: Compiled `.js` files, manifest.json, assets

**`tests/`:**
- Purpose: Vitest test suite
- Contains: Unit and integration tests for generators, scorers, verifier
- Key patterns: Each test file mirrors a source module (e.g., `tests/xpath.test.ts` tests `src/core/xpath-generator.ts`)

**`manifests/`:**
- Purpose: Browser-specific manifest templates
- Contains: Chrome and Firefox manifest.json templates (some keys differ)
- Build process: `copy-manifest.cjs` selects template based on `BROWSER` env var, copies to `public/`

**`scripts/`:**
- Purpose: Build-time utilities
- Contains: Post-build manifest copy script
- Key file: `copy-manifest.cjs` — copies correct manifest template after Vite build

## Key File Locations

**Entry Points:**
- Background service: `src/background/background.ts` — listens on keyboard shortcut, initiates toggle
- Content script: `src/content/index.ts` — injected into page, message listener, overlay lifecycle
- Popup: `src/popup/main.ts` — builds UI on DOMContentLoaded
- Main selector logic: `src/core/selector-engine.ts` — called by content script after element click

**Configuration:**
- Build config: `vite.config.ts` — multi-entry build (background, content, popup), IIFE wrapper for content script
- TypeScript: `tsconfig.json` — strict mode, ES2020 target, `@/` path alias to `src/`
- Testing: `vitest.config.ts` — jsdom environment, auto-glob discovery in `tests/`
- Manifests: `manifests/chrome/manifest.json`, `manifests/firefox/manifest.json` — browser-specific configs

**Core Logic:**
- Selector orchestration: `src/core/selector-engine.ts` — entry point for generation
- XPath strategies: `src/core/xpath-generator.ts` — 13 candidate generation methods
- CSS strategies: `src/core/css-generator.ts` — 15 candidate generation methods
- Playwright locators: `src/adapters/playwright-adapter.ts` — 12 locator formats
- Verification: `src/core/locator-verifier.ts` — runtime type detection & DOM evaluation

**Testing:**
- Selector engine tests: `tests/selector-engine.test.ts`
- XPath tests: `tests/xpath.test.ts` — generator & scorer
- CSS tests: `tests/css.test.ts` — generator
- Playwright tests: `tests/playwright-adapter.test.ts`

## Naming Conventions

**Files:**
- Kebab-case: `event-manager.ts`, `selector-engine.ts`, `xpath-generator.ts`
- No index re-exports; each file exports its primary symbol directly
- `.test.ts` suffix for Vitest test files

**Directories:**
- Lowercase, descriptive: `background/`, `popup/`, `content/`, `core/`, `adapters/`, `types/`, `utils/`
- No single-file directories (except `types/` and `utils/` which contain helpers)

**Functions:**
- camelCase: `getLocatorsForElement()`, `generateRankedXPaths()`, `scoreXPath()`
- Verb-prefix pattern: `generate*`, `score*`, `analyze*`, `verify*`

**Types/Interfaces:**
- PascalCase: `ElementLocators`, `ScoredXPath`, `AttributeAnalysis`, `VerifyResult`
- `*Result` suffix for return types from verifier/analyzer
- `*Breakdown` suffix for factor breakdowns in scores

**Variables:**
- camelCase for local variables and constants
- UPPER_SNAKE_CASE for module-level constants (e.g., `TEST_ID_ATTRS`, `WEIGHT_STABILITY`)

## Where to Add New Code

**New Locator Format (e.g., Appium, WebDriver):**
- Create `src/adapters/[framework]-adapter.ts` following `playwright-adapter.ts` pattern
- Export `generateRanked[Framework]()` function
- Import and call from `src/core/selector-engine.ts`
- Create scorer in `src/core/[framework]-scorer.ts` if custom weights needed
- Add type to `LocatorFormat` union in `src/types/locator.types.ts`

**New XPath/CSS Generation Strategy:**
- Add method to `collectXPathCandidates()` or `collectCSSCandidates()` in respective generator
- Method should check for specific attribute/property, create candidate(s), avoid duplicates
- Strategy must have a descriptive label (e.g., `'id-contains'`, `'tag-class'`)
- Test with `tests/xpath.test.ts` or `tests/css.test.ts`

**New Scoring Factor:**
- Add sub-score function in `src/core/[format]-scorer.ts`
- Update weight constants to sum to 1.0
- Add factor to `*ScoreBreakdown` type in `src/types/locator.types.ts`
- Update weighted formula in scorer's main function

**Utility Function:**
- Add to `src/utils/dom-utils.ts` (if DOM-related) or `src/utils/string-utils.ts` (if string-related)
- Test in isolation if complex

**Test for New Feature:**
- Create `tests/[feature].test.ts` using Vitest + jsdom
- Mirror import path from source (e.g., test `src/core/xpath-generator.ts` in `tests/xpath.test.ts`)
- Use synthetic DOM elements; no real pages needed

## Special Directories

**`public/`:**
- Purpose: Built extension files (output from Vite)
- Generated: Yes (by `npm run build` → Vite)
- Committed: Yes (committed to git for fast CI/clones)
- Output location: Configured in `vite.config.ts` via `process.env.VITE_OUT_DIR` (default: `public`, for CI: `dist`)

**`.planning/codebase/`:**
- Purpose: GSD (Gold Standard Docs) analysis documents
- Generated: No (manually written by agents)
- Committed: Yes (reference for future work)
- Contents: `ARCHITECTURE.md`, `STRUCTURE.md` (this file), `TESTING.md`, `CONVENTIONS.md`, `STACK.md`, `INTEGRATIONS.md`, `CONCERNS.md`

**`manifests/`:**
- Purpose: Template manifests for browser-specific builds
- Generated: No (hand-maintained)
- Committed: Yes
- Note: Build script copies appropriate template to `public/manifest.json` based on `BROWSER` env var

## Build & Output Structure

**Development Build:**
```bash
npm run dev              # Vite watch mode
# → public/background.js
# → public/content.js (wrapped in IIFE)
# → public/assets/popup.js
# → manifest copied by copy-manifest.cjs
```

**Production Build (Chrome):**
```bash
npm run build:chrome     # TypeScript compile + Vite + manifest copy
# → public/
# (ready to zip and upload to Chrome Web Store)
```

**Production Build (dist/):**
```bash
npm run build:dist:chrome  # For CI/distribution
# → dist/ (empty dir, Vite fills)
# (Useful for artifact storage, separate from watch-mode public/)
```
